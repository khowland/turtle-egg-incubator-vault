## Part A: 🔴 CRITICAL — Session Persistence Failure (Blocker)

### Problem Statement

The First Intake save button triggers a **complete save abort** with the error:
`🔴 CRITICAL: Records could not be saved! Forensic session persistence failure. Clinical commit aborted.`

### Root Cause Trace

The call chain is:
1. `Intake.tsx` → `handleSubmit()` → `ensureSessionPersisted(observer, supabase)` [Intake.tsx:269]
2. `identity.ts:ensureSessionPersisted()` first SELECTs the `session_id` in `session_log`
3. If not found, it INSERTS a row with `session_id: observer.session_id` [identity.ts:30]
4. **SCHEMA MISMATCH:** `session_log.session_id` is `bigint GENERATED ALWAYS AS IDENTITY` — this prevents manual INSERT of the `session_id` value
5. The INSERT silently fails (or throws) → `throw new Error('Forensic session persistence failure. Clinical commit aborted.')`
6. Error caught at `Intake.tsx:367` → user sees the critical error message

**Exact Schema Definition (2026-05-22):**
```
CREATE TABLE public.session_log (
  session_id bigint GENERATED ALWAYS AS IDENTITY NOT NULL,
  CONSTRAINT session_log_pkey PRIMARY KEY (session_id)
);
```

### Root Cause History

The `session_id` used to be a manually-assigned bigint (e.g., `BigInt(Date.now())`).
During the sovereignty refactor (TSK-04, ~2026-05-12), the schema was changed to
`GENERATED ALWAYS AS IDENTITY` but the frontend code in `identity.ts` was **not updated**
to match. The RPC functions (`vault_finalize_intake`) may also still pass `session_id`.

### Required Fix

**Option A (Recommended — minimal schema change):** Alter `session_log.session_id` from
`GENERATED ALWAYS` to `GENERATED BY DEFAULT`. This allows the frontend's manual assignment
to work while still auto-generating for new rows.

```sql
ALTER TABLE public.session_log 
ALTER COLUMN session_id DROP IDENTITY IF EXISTS;

ALTER TABLE public.session_log 
ALTER COLUMN session_id ADD GENERATED BY DEFAULT AS IDENTITY;
```

**Option B (Cleaner — keep ALWAYS, fix frontend):** Remove `session_id` from the INSERT in
`identity.ts:ensureSessionPersisted()` and update the observer `session_id` with the
returned value from the DB. This requires the INSERT to RETURN `session_id`.

|:---|:---|:---|
| `supabase_db/migrations/` | New migration file | ALTER session_log.session_id to BY DEFAULT |
| `frontend/src/lib/identity.ts` | 24-35 | Fix INSERT (remove session_id or use RETURNING) |
| `frontend/src/context/SessionContext.tsx` | 50-80 | May need to sync observer.session_id after fix |

## Part B: Schema Extension — Replace Days In Care with Disp. Date + SCL

### Current Schema State (intake table)

```
days_in_care numeric,          ← REMOVE THIS
```

### Required Schema Changes

1. **Remove column:** `days_in_care` from `public.intake`
2. **Add column:** `disp_date date` (Disposition Date — nullable, since it's set at disposition)
3. **Add column:** `scl numeric` (Straight Carapace Length in mm — nullable, measured at intake)

### Migration SQL

```sql
-- Step 1: Remove days_in_care
ALTER TABLE public.intake DROP COLUMN IF EXISTS days_in_care;

-- Step 2: Add disp_date (Disposition Date)
ALTER TABLE public.intake ADD COLUMN disp_date date;

-- Step 3: Add SCL (Straight Carapace Length)
ALTER TABLE public.intake ADD COLUMN scl numeric;
```

### Frontend UI Changes (Intake.tsx)

| Current Field | Replacement | Type | Notes |
|---|---|---|---|
| `Days in Care` (number_input) | `Disp. Date` (date input) | `input type="date"` | Same position in form |
| None | `SCL` (number input) | `input type="number" step="0.1"` | Placed next to other measurement fields |

The `disp_date` field should appear in the main intake form section.
The `SCL` field should have a label "Straight Carapace Length (mm)" with a compact number input next to it.

Both fields are optional (nullable) — they don't need to block form submission.

### Files Affected

| File | Lines | Change |
|:---|:---|:---|
| New Supabase migration | New file | DROP days_in_care, ADD disp_date, ADD scl |
| `frontend/src/pages/Intake.tsx` | ~105-115 | Replace `daysInCare` state with `dispDate` + `scl` |
| `frontend/src/pages/Intake.tsx` | ~320-330 | Update RPC payload to include new fields |
| `frontend/src/pages/Intake.tsx` | ~515-530 | Replace number_input with date input + SCL input |
