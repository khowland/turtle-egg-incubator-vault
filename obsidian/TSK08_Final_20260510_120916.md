# TSK-08 Final Resolution

> [!success] 6/6 TESTS PASSING

## Root Causes

### Failure 1: SQLi WINC Case # test (WAF 403)
The test `test_sqli_payload_in_winc_case_field_sanitized` queried Supabase with `eq('intake_name', payload)` where payload contained SQL injection strings. Supabase's Cloudflare WAF blocked the request, returning a 403 HTML page. The test design needed a safe lookup key.

### Failure 2: XSS storage test (assertion failure)
The test `test_xss_payloads_sanitized` queried `eq('intake_name', sig)` but `intake_name` stores the WINC Case # value (the XSS payload), not the unique signature `sig`. This caused `len(intake_res) == 0` and the test failed. Additionally, original assertions checked for raw SQL keywords, but the app uses `html.escape` which encodes `<`, `>`, `&`, `'`, `"` to HTML entities, leaving keywords like `DROP TABLE` as plain text (safe). The tests were too strict.

## Fixes Applied

### Patch 1: SQLi success path
- Changed DB lookup from `eq('intake_name', payload)` to `eq('finder_turtle_name', sig)` to avoid triggering Cloudflare WAF.
- Removed redundant keyword blacklist checks (parameterized queries prevent SQLi).

### Patch 2: SQLi reject path
- Changed DB lookup similarly to safe column.

### Patch 3: XSS success path
- Changed DB lookup to `eq('finder_turtle_name', sig)`.
- Replaced keyword checks with assertion that no raw `<` or `>` remain, verifying `html.escape` was applied.

### Patch 4: XSS reject path
- Changed DB lookup to safe column.

## Outcome
All 6 adversarial input tests now pass:
1. TC-ADV-INP-01: SQLi Finder
2. TC-ADV-INP-02: SQLi WINC Case #
3. TC-ADV-INP-03: Empty fields
4. TC-ADV-INP-04: XSS WINC Case #
5. TC-ADV-INP-05: Long fields
6. TC-ADV-INP-06: XSS Finder

## Security Note
The app's sanitization via `html.escape` is sufficient to prevent XSS and SQLi via parameterized Supabase queries. No weakening of security code was needed; test assertions were aligned with actual defense mechanisms.
