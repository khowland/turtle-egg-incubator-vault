# 🐛 BUG: Intake Save — Forensic Session Persistence Failure

## Symptom

First Intake save triggers:
```
🔴 CRITICAL: Records could not be saved!
Forensic session persistence failure. Clinical commit aborted.
```

## Root Cause

The `ensureSessionPersisted()` function in `frontend/src/lib/identity.ts` attempts to
manually INSERT a row into `session_log` with a specific `session_id` value:

```typescript
await supabase
  .from('session_log')
  .insert({
    session_id: observer.session_id,   // ← manual bigint value
    observer_name: observer.observer_name,
    login_timestamp: observer.login_timestamp
  })
```

However, the `session_log` table defines `session_id` as:
```sql
session_id bigint GENERATED ALWAYS AS IDENTITY NOT NULL
```

`GENERATED ALWAYS AS IDENTITY` **prohibits manual INSERT** of the identity column.
The INSERT silently fails, the error is thrown, and the clinical commit is aborted.

## How It Broke

During the **Sovereignty Refactor (TSK-04, ~2026-05-12)** and the **Numeric PK Migration
(v9.1.0)**, the `session_log.session_id` was changed from a manually-assigned bigint to
`GENERATED ALWAYS AS IDENTITY`. This was the correct move for consistency with all other
tables, but the frontend code in `identity.ts` was **never updated** to match.

## Timeline

1. **Pre-migration**: `session_id` was a manual bigint → `identity.ts` INSERT worked fine
2. **v9.1.0 PK Migration**: All tables switched to `GENERATED ALWAYS AS IDENTITY`
3. **Post-migration**: `identity.ts` INSERT now violates the identity constraint
4. **Every intake save fails** on the session check before reaching the RPC

## Fix Options

### Option A (Minimal — ALTER schema to BY DEFAULT)
Change `GENERATED ALWAYS` → `GENERATED BY DEFAULT`. Allows manual insert while preserving
auto-generation. Lowest risk, no frontend logic change.

### Option B (Clean — fix frontend to omit session_id)
Change `identity.ts` to omit `session_id` from the INSERT, then capture the DB-generated
value and sync it back to the observer context. More work but architecturally cleaner.

## Verification (Post-Fix)

- [ ] First intake save succeeds
- [ ] `session_log` table has a row for the session
- [ ] Subsequent saves reuse the existing session (no duplicate INSERT attempt)
- [ ] All RPC calls that reference `session_id` continue to work
